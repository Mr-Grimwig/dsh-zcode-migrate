# 需求说明书 — dsh-zcode-migrate（ZCode → DSH 会话与思路迁移插件）

> 版本 v1.0 · 2026-09-18 · 状态：已与需求方对齐的验收基准

## 1. 背景与问题

- 需求方正在从 **ZCode**（智谱 Z.ai 出品的 Agentic 开发环境，桌面端 + CLI，会话存在本机 `~/.zcode/`）迁移到 **DSH**（DeepSeek Harness，DeepSeek 开源 Agent 框架，插件化）。
- ZCode 官方没有会话导出能力，官方 FAQ 明确"会话历史不建议搬运"；会话一旦留在 ZCode 里，换工具就意味着**丢失全部上下文与思考轨迹**。
- 需求方不接受"重新开一段会话、把旧记录贴进去让模型读"的做法——那会让模型把历史当外部材料，思路（thinking）也会被重新生成，等于失忆。

## 2. 目标与非目标

### 2.1 目标（一句话）

做一个 DSH 插件，把 ZCode 本地的**聊天记录与思路**完整迁移为 **DSH 原生会话**，使迁移后的会话**可以直接续聊（接上）**，且**历史思维逐字不变**。

### 2.2 非目标（明确排除）

- ❌ 不做"总结旧会话 → 开新会话"式迁移；
- ❌ 不做"把历史整段塞进一条消息让模型阅读"式迁移；
- ❌ 不修改 ZCode 源侧任何数据（全程只读）；
- ❌ 不自动注册 MCP/记忆等带副作用的配置（仅可生成提示文本，默认关闭）；
- ❌ 不承诺续聊后"未来新产生的思考"与不换 harness 时逐字相同（物理上不可能，见 §7）。

## 3. 使用场景

1. 需求方在 ZCode 中积累了若干项目会话（含大量思考过程），决定转用 DSH；
2. 安装本插件 → 扫描 → 一键导入；
3. 在 DSH 侧边栏看到原会话出现在对应项目工作区下，打开可见完整对话与思路原文；
4. 直接在 DSH 里继续该会话，模型以"自己之前说过的话、想过的思路"为基础往下走；
5. 之后 ZCode 侧若还有残留更新，可再次执行导入，只追加增量。

## 4. 功能性需求

### FR-1 数据源发现与读取（只读）

- FR-1.1 自动定位 ZCode home：`--source 指定` > `$ZCODE_HOME` > `~/.zcode`；
- FR-1.2 主数据源：`cli/db/db.sqlite`（session / message / part 三表；思考在 part 表的 `reasoning`/`thinking` 行）；以只读方式打开，带 busy_timeout，ZCode 运行中也可读；
- FR-1.3 兜底数据源：`cli/rollout/model-io-<sessionId>.jsonl`（sqlite 缺失/损坏时启用）；
- FR-1.4 旧版兼容：`~/.zcode/projects/**/*.jsonl`（3.0 之前内嵌 Claude 运行时的格式），默认可开关；
- FR-1.5 一切读取异常降级为警告，不中断整体导入，不抛出导致插件崩溃的错误。

### FR-2 内容覆盖范围

每条会话迁移：标题、创建/更新时间、工作区路径、模型/provider 信息；每条消息迁移：角色、时间、正文；以及：

- FR-2.1 **思考/推理内容（核心对象）**：全量、逐字；
- FR-2.2 工具调用（名称、入参原文 JSON）与工具结果（含错误态）；
- FR-2.3 文件附件引用（保留 url/元信息；无法还原的降级为占位文本并记警告）。

### FR-3 思路保真规则（最高优先级）

- FR-3.1 **逐字**：reasoning 文本从源到目标逐字节相等（`===`），不 trim、不截断、不转义改写、不摘要、不重新生成；
- FR-3.2 **无模型参与**：迁移管线为纯确定性数据变换，不调用任何 LLM；
- FR-3.3 **保序**：多段思路之间、思路与正文之间的相对顺序保持源会话原貌；
- FR-3.4 **空块如实报告**：源侧即为空串的 reasoning（第三方 provider 过滤所致）跳过并在报告中计数，标注"源侧缺失，非迁移丢失"。

### FR-4 DSH 原生会话生成

- FR-4.1 以 DSH 标准事件格式写入：`turn/start`、`user/message`、`assistant/message`（思路为 content 内 `{type:'reasoning'}` 块）、`tool/call`、`tool/result`、`step/end`、`turn/end`、`session/title`；
- FR-4.2 每个工具调用恰配一个工具结果；源缺结果的合成占位结果并计数（保证续聊时 API 合法）；
- FR-4.3 只使用 DSH 内置事件词汇，不写自定义事件（保证任何 DSH 构建都能读）；
- FR-4.4 写入走 `sessionPersistence` 官方 API（兼容新旧两代），绕过校验的直接写盘仅作备选；
- FR-4.5 按源会话的工作区路径归位：解析/创建工作区并挂载会话，侧边栏可见。

### FR-5 续聊语义（"接上"而非"阅读"）

- FR-5.1 迁移产物是可 resume 的活会话：历史消息以原生角色事件存在，模型续聊时视其为自己的历史；
- FR-5.2 历史思考在 DSH 界面以 Think 块形式可见可回溯；
- FR-5.3 续聊时历史思维是否随请求回传模型，遵循 provider 的 API 规则——只要求与"留在 ZCode 里"的行为一致（主流厂商默认不回传历史 reasoning，ZCode 亦然）。

### FR-6 增量同步与幂等

- FR-6.1 重复导入幂等：同一会话不产生重复 DSH 会话（稳定的目标会话 id + 注册表）；
- FR-6.2 增量追加：源会话变长且前缀一致时，只追加新增部分，不覆盖已迁移内容；
- FR-6.3 前缀被改写等冲突情形：拒绝原地重写，提示用 `--force` 生成全新副本，由人决定。

### FR-7 用户界面

- FR-7.1 斜杠命令 `/zcode-import scan|all|status`（扫描 / 导入 / 状态）；
- FR-7.2 设置面板：源目录覆盖、旧版兼容与兜底开关、一键扫描/导入按钮；
- FR-7.3 导入报告：会话数、思路块数、空块数、工具配对数、事件数、警告清单，落盘可查。

### FR-8 安全与降级

- FR-8.1 对 ZCode 只读；对 DSH 只新增会话，不改动已有会话；
- FR-8.2 可选服务（命令、设置页、工作区）缺失时优雅降级，核心导入能力不受影响。

## 5. 非功能性需求

- NFR-1 兼容：ZCode 3.x 自研内核格式为主，旧版 JSONL 尽力兼容；DSH developer preview 的新旧两代持久化 API 双路兼容；
- NFR-2 性能：百级会话、单会话十万字级思路文本可顺利完成；超长文本不做任何截断；
- NFR-3 可验证：迁移前后思路逐字 diff 可由插件/测试自动执行并输出结果；
- NFR-4 可维护：ZCode 无官方导出契约（schema 可能漂移），解析层需集中、字段回退链清晰，便于跟进。

## 6. 验收标准（可逐项检查）

- AC-1 端到端：仿真 ZCode 库 → 迁移 → DSH 会话中的 reasoning 与源**逐块 `===` 相等**（含超长/emoji/代码块/中英混排用例）；
- AC-2 事件流合法：骨架顺序正确、seq 连续、每个 tool-call 恰有一个 tool/result；
- AC-3 幂等与增量：重复导入跳过；源追加后只补尾巴；前缀改写被拒绝；
- AC-4 工程：`npm run build` 通过、测试全绿、插件清单（package.json / cordis.patch.yml）完整；
- AC-5 报告：空 reasoning 块等源侧缺失项在报告中如实计数。

## 7. 已确认的边界共识

1. 保真对象是**已发生的历史思维**；续聊后新产生的思考不作逐字相同的承诺（不换 harness 也做不到）；
2. 历史思维是否回传模型取决于 provider 规则，与留在 ZCode 行为一致即满足要求；
3. 源侧本身缺失的内容（如被过滤的空 reasoning）如实提示，不算迁移丢失。

## 8. 术语

- **思路**：ZCode/DSH 会话中 assistant 的思考（thinking/reasoning）内容；
- **原生会话**：以 DSH 标准事件格式持久化、可 resume 的会话，区别于"导出文本/贴入记录"；
- **接上**：模型把迁移历史当作自己的对话历史继续生成；**阅读**：模型把历史当外部输入材料。本需求只要前者。
